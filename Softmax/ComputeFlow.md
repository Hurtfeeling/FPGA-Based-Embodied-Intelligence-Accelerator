# Softmax FP32 四阶段计算流程

更新日期：2026-11-02。本版以“输入行 BRAM + 输出行 BRAM，归一化结果写回输出 BRAM，最后写 DDR”为准。每行最多 4096 个 FP32，一次 START 自动完成 M×K 矩阵。已实现 Verilog .v 流水 RTL，目标时钟为 250 MHz；行缓存采用 4-bank BRAM 推断结构。本文说明当前版本的计算和数据流，接口与完整调度见 [Plan.md](Plan.md)。## 1. 数学过程

对当前行：

~~~
m    = max(x[0], ..., x[K-1])
z[i] = x[i] - m
e[i] = exp(z[i])
S    = sum(e[i])
p[i] = e[i] / S
~~~

这是稳定Softmax计算。有效有限输入满足z<=0，减最大值不改变精确数学下的Softmax结果。

## 2. 两块 BRAM

| BRAM | 阶段中的内容 | 端口 |
|---|---|---|
| input_buffer | 当前行x；已读位置可被下一行x覆盖 | 同步1读+1写，各128 bit |
| output_buffer | 先保存当前行e，归一化后原位变为p | 同步1读+1写，各128 bit |

~~~
每块容量 = 4096 × 32 bit = 1024 × 128 bit = 16 KiB
两块合计 = 32 KiB
RX/TX FIFO 各32×128 bit，合计1 KiB
~~~

两块指总共一块input和一块output。每块使用4个1024×32-bit BRAM bank，共用地址/使能，对应4个FP32 lane；一拍同步读，不清零存储阵列。exp ROM、浮点流水及控制另计；采用两份各8 KiB双读exp表时，已列存储payload共约49 KiB。RAMB36、LUTRAM/寄存器与 ROM 的实际映射以当前 RTL 版本的综合报告确认。小队列继续使用LUTRAM/寄存器，浮点流水和tag另占寄存器。

## 3. 第一步：加载，并逐拍比较最大值

~~~
AXI R → RX FIFO → input_buffer 写入4个x
                              └→ key寄存 → 4路独立lane最大值 → 两级合并 → m_load
~~~

每个128-bit beat包含4个FP32。输入按DAZ处理后转成可排序的IEEE key，用无符号比较更新4个独立lane最大值，再两两合并、最终合并。max路径共4级，避免同一拍串行比较4个lane。尾beat无效lane不参与有效值判断。全部W=ceil(K/4)个word写入、DMA结束且4级max流水排空后，锁存input_max；开始EXP时再复制为m_calc。

后续预取下一行时重新使用独立的m_load，不能改变正在计算的m_calc。

## 4. 第二步：四路减法接exp，写output并求和

~~~
input读4个x
    ↓
4路FP32减法：z=x-m_calc，10级
    ↓
4路乘log2(e)，8级 → LUT插值/FP32打包，9级
    ├→ 打包4个e，写output_buffer
    └→ 四路指数/尾数对齐UQ16.48 → 前向CSA → 反馈CSA → 行末S
~~~

softmax_exp4内部共10+8+9=27级，不需要缓存整行差值z。无背压时每拍接收一组4个FP32，流水深度只影响首结果和收尾。BRAM读返回队列及其后隔离寄存器的延迟另外计算，数据/keep/tag由valid/ready同步控制。

exp的存储和求和两个分支必须各消费同一结果一次；任何一支停顿都不能导致另一支重复消费。求和支路将e转成q=roundEven(e×2^48)。四输入先压成U/V，再与上一拍A/B做4:2压缩并寄存。行末才完整相加T=A+B，转换S=FP32(T×2^-48)。两个累加寄存器各64位，每拍接收4个e。具体顺序为4级定点转换、1级前向CSA、1级反馈CSA，行尾再进行一次进位加法；最后一个输入握手沿到整数sum有效沿相隔6拍，随后5级转换生成FP32行和。详细RTL实现及1024×1024算例见 [RTLImplementation.md](RTLImplementation.md)。

此时同时加载下一行到input，但要遵守：

~~~
先安全读出 input[j] 的当前行x
再允许把下一行x写入 input[j]
~~~

“安全读出”指BRAM读返回已被有容量保证的寄存器/流水接管，不只是发出读请求。读写同一地址错开周期。当前行的max与下一行的max分开保存。

第二步结束条件是所有e已经实际写入output，且S完成归约；不能在最后一组x刚进入exp时就开始归一化。

## 5. 第三步：output读e，归一化，原位写p

数学上每个元素计算：

~~~
p[i] = e[i]/S
~~~

当前硬件每行先计算一次r=1/S，再用8级4路FP32乘法流水计算p=e*r。一般倒数需要48次恢复除法迭代，再以3拍分别比较余数、舍入和打包；S为2的整数次幂时走1级精确旁路。这样可减少除法资源，但与逐元素FP32直接除法可能有舍入差异，需要参考模型核对误差。

~~~
output读e → 4路归一化 → output原地址写p
~~~

原地址随运算流水传递。旧e先读出，计算完成再写回p；禁止重复读取已经覆盖的地址。全部p写回后，才能开始该行第四步。

该阶段占用output读写两个端口，因此下一行EXP不能同时满速写output。此时input可保存已预取的下一行，或继续完成尚未结束的加载。

## 6. 第四步：读output中的p，写回DDR

~~~
output读p → TX FIFO → AXI W → DDR
~~~

输出按行和列顺序发送。尾word无效lane填FP32+0。TX FIFO及读返回寄存器需应对AXI背压。最后一个W beat不代表任务完成，整矩阵DONE须等待所有B响应成功及相关流水排空。

## 7. 行间流水如何安排

基础安排已经能把下一行LOAD与当前行EXP重叠：

| 时段 | 输入侧 | 输出侧 |
|---|---|---|
| 0 | 加载行0并求max | 空闲 |
| 1 | EXP读取行0，同时逐字加载行1 | 写入行0的e，并求S |
| 2 | 保留/继续加载行1 | 行0归一化，e原位改为p |
| 3 | 保留/继续加载行1 | 行0的p写DDR |
| 4 | EXP读取行1，同时逐字加载行2 | 写入行1的e，并求S |

当前默认启用STORE/EXP重叠（OVERLAP_STORE_EXP=1）：第四步output只使用读口，在旧p安全读出后，用写口接收下一行e：

~~~
LOAD 行0
EXP 行0 + LOAD 行1
NORM 行0
STORE 行0 + EXP 行1 + LOAD 行2
NORM 行1
STORE 行1 + EXP 行2 + LOAD 行3
...
~~~

此时input和output都需要独立的安全覆盖计数：

- input新x写入地址，只能位于当前x已经安全读出的范围。
- output新e写入地址，只能位于旧p已经可靠交给TX/写通路的范围。

重叠调度中，DDR停顿会限制output空间回收，并向exp、input读取和加载传播背压。固定延迟且不能暂停的FP流水，须在发射前为在途结果预留足够空间。

下一行NORM仍须等本行所有e写入、sum完成、旧行output读取全部结束。旧行W/B未结束时，继续保留其独立地址和响应上下文。

## 8. 吞吐和边界

K=4096时每阶段主体扫描W=1024个word。四阶段首次完整输出理想约4W拍；输入预取重叠后，基础稳态约3W拍/行；如果进一步把旧行STORE和新行EXP重叠，理想可接近2W拍/行。

output每行需要W次写e、W次读e、W次写p、W次读p；一读一写端口的稳态带宽下界就是2W拍/行。实际还要加FP流水尾部、归约/倒数、回收等待及AXI停顿，不能承诺每W拍完成一行。

~~~
DIM_MK低16位 = M-1，M≤65536
DIM_MK高16位 = K-1，K≤4096
ROW_BYTES = 16×ceil(K/4)
row_addr = BASE + row×ROW_BYTES
~~~

SRC/DST按16-byte对齐且不重叠，K非4倍数时每行补齐到完整beat。一条START完成全部M行，每行外部读写各一次。

-inf按mask输出0；NaN/+inf及全mask行报错。各阶段分别确认数据、地址及本行归约完成后再推进；最终DONE等待全部输出及AXI响应成功。数值语义和异常收尾详见Plan.md。

## 9. 启动与250 MHz预算

软件只配置4个AXI-Lite寄存器并START一次。模块立即置BUSY，以4拍完成矩阵长度和地址合法性检查；通过后按行生成读写命令，地址每次递增ROW_BYTES。全矩阵结束仍以最后一个B响应及相关流水排空为准。

对于1024×1024矩阵，每行W=256拍、每块BRAM使用4 KiB，输入/输出各4 MiB。理想重叠主体为(2M+2)W=524800拍；250 MHz下为2.0992 ms，但此数未包含27级exp、8级归一化、max/sum排空、5级行和转换、倒数和AXI停顿。不能把流水II=1直接当作完整矩阵的吞吐。完整周期需运行当前版本回归或 PYNQ 实测，并报告对应时钟、AXI 测试条件和计时边界。
