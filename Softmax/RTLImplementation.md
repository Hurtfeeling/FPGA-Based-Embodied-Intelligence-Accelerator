# Softmax RTL实施约定

按固定 input/output 两块行 BRAM 和四阶段流程实现，设计时钟目标为 250 MHz（4 ns）。全部 RTL 与测试台使用 `.v`，公共函数使用 `.vh`，按 Verilog-2005 编译。BRAM bank 结构与时序细节以当前源码为准；每次修改后都应重新运行仿真及 Vivado 综合/实现。

## 模块与接口

| 模块 | 职责 |
|---|---|
| softmax_accelerator_top | AXI-Lite32/AXI-full128；默认控制基址0x80010000；复用GEMM duplex DMA |
| softmax_axil_regs | 四个寄存器；AW/W独立、WSTRB、busy写保护、非法访问SLVERR |
| softmax_core | 两块1024×128 bit同步1R1W BRAM、输入预取、STORE/EXP重叠、安全回收、矩阵调度和异常收尾 |
| softmax_fp32_sub4 | 10级四路FP32 x-max，II=1 |
| softmax_fp32_mul4 | 8级四路FP32乘共同scale；分别用于log2(e)和归一化，II=1 |
| softmax_exp4 | 10级减法+8级乘log2(e)+9级LUT后端，共27级，携带10位word地址tag |
| softmax_sum4 | 4级FP32转UQ16.48、前向4:2压缩、反馈4:2压缩和行尾64位进位加法 |
| softmax_sum_to_fp32 | 行和范围[1,4096]专用5级定点转FP32流水 |
| softmax_recip | 每行一次倒数；48次恢复除法迭代+3拍收尾；2的整数次幂1级精确旁路 |
| softmax_norm4 | 调用8级FP32乘法，结果按原地址写回output BRAM |
| softmax_storage | RX队列、同步行BRAM、读返回队列和输入隔离寄存器 |
| softmax_row_bram | 位于softmax_storage.v；4个1024×32-bit BRAM bank组成一个16 KiB行缓存，共用地址/使能 |

valid/ready停顿期间保持数据和tag稳定。exp写output和送sum使用同一个提交事件，保证每个结果恰好写入和累加一次。BRAM读返回必须提前预留队列容量，safe_count只在返回数据可靠入队后增加。OVERLAP_STORE_EXP默认1，参数0用于基础调度对照。

## 加载求最大值

数据写入input BRAM时立即进入4级max路径：

~~~
4个FP32 → DAZ/可排序key捕获 → 4路独立lane最大值 → 两两合并 → 最终合并/还原FP32
~~~

非负数key为`{1'b1,x[30:0]}`，负数key为`~x`；用无符号比较实现浮点顺序。每路只把自己的历史最大值与新值比较，反馈中没有4路串行比较链。有效输入的NaN/+inf单独报错；-inf mask及无效尾lane不参与有效数据计数。

最后一个加载beat之后排空4级valid，同时等待DMA结束及RX队列排空，再发布input_max。开始EXP时把它复制到calc_max，下一行加载使用自己的lane_max状态。预取不会改变正在计算的一行的最大值。

## exp与归一化流水

| 路径 | 流水分级 |
|---|---|
| FP32减法，10级 | 捕获、解包、幅值选择、对阶、尾数加减、前导1检测、规格化、下溢移位、RNE、打包 |
| FP32乘法，8级 | 捕获、解包、DSP部分积、部分积合并、规格化、下溢准备、RNE、打包 |
| exp后端，9级 | 移位解码、FP32转定点、ROM读取、ROM输出寄存、插值乘法、drop舍入、插值减法、尾数RNE、FP32打包 |

完整softmax_exp4的27级不包含BRAM读返回队列及其后的1级隔离寄存器。27级表示无停顿寄存深度；持续输入时仍然每拍产生一组4个exp，不能把27级当成每组占用27拍。

范围归约采用`d=abs(x-max)`、`t=d×log2(e)`；拆出整数n和小数f，用1024段ROM线性插值求`2^-f`，最后调整指数得到`2^(-n-f)`。ROM源文件每项64位，包含UQ1.30的base和相邻差drop，段内插值小数13位。

drop最大726572，实际只需20位，因此每路20×13插值乘法使用1个DSP。插值结果位于[0.5,1]，FP32规格化只需二选一，不再使用通用前导1检测和动态大移位。FP32乘法的24×24尾数乘法拆成24×17和24×7，在DSP部分积后寄存，再合并。log2(e)共8个DSP、插值4个、归一化8个，启动尺寸计算另用1个，总21个DSP。

每行S仅计算一次倒数。一般输入用48次恢复除法迭代，随后余数比较、RNE、打包各1拍；迭代减法借位同时给出比较结果。S为2的整数次幂时精确调整指数，走1级旁路。四路8级归一化计算`p=e×(1/S)`，结果原位写output；它可能与逐元素直接除法有舍入差异。

输入subnormal按DAZ，结果先RNE再FTZ。-inf输出0；NaN/+inf及全mask行由core报错。极端有限值相减溢出及exp下溢需在范围转换和打包时处理，禁止指数截断环绕。RTL不使用real或仿真系统函数替代算术硬件。

## 四路进位保存累加

~~~
FP32 normal: e=M×2^(E-150)，M含隐藏位，共24位
q=RNE(e×2^48)=RNE(M×2^(E-102))

q0+q1+q2+q3 → U+V
A+B+U+V → A_next+B_next

3:2压缩：sum=a^b^c，carry=((a&b)|(a&c)|(b&c))<<1
行末：T=A+B，S=FP32(T×2^-48)
~~~

定点转换共4级：指数/尾数准备、低位移位、高位移位与sticky累积、RNE寄存。随后1级前向4:2压缩和1级反馈4:2压缩，每拍接收4个exp。反馈由两层3:2逻辑组成，没有64位进位传播；只有行末做一次完整64位加法。

从最后一个输入握手沿到m_sum有效沿相隔6拍，控制依据valid确认完成。随后softmax_sum_to_fp32用5级完成行和捕获、有限范围前导1/指数准备、移位对齐、RNE和打包。S至少为1，因为每个有效行的最大元素exp为1；K≤4096时T≤2^60，64位足够。入口定点化累计绝对误差≤K×2^-49，K=4096时约7.28e-12；exp误差和最终FP32舍入另计。

output BRAM保存FP32 exp，UQ16.48仅用于求和支路。行边界等待末token进入累加器、最终进位加法和FP32转换完成后，再请求倒数；不能在exp输入发完时提前读sum。

## 控制路径与存储

START立即置BUSY，配置检查拆为4拍：矩阵word数乘法、字节数、33位地址端点加法、范围/重叠判定。通过后才开始DMA；配置非法返回ERROR_CODE=1。每行DMA命令使用各自next_rd_addr/next_wr_addr，握手后递增ROW_BYTES，避免每行地址乘法成为关键路径。

input和output分别实例化`softmax_row_bram`，各16 KiB。每个模块显式生成4个1024×32-bit bank，每个bank带`ram_style="block"`属性，lane n对应`wdata/rdata[n*32+:32]`。各bank共用地址/使能，独立同步写口和读口合并为128 bit，一拍读延迟；`ren=0`时保持读数据。阵列及读数据不复位，由reader的valid屏蔽无效内容，以保持BRAM推断和现有读返回时序。

按目标器件每块行缓存预计4个RAMB36，两块共8个；exp两份双读表保留`rom_style="block"`，ROM综合资源需由当前版本 Vivado 报告确认。本次未重跑综合，实际资源和时序待确认。RX与STORE/TX各32拍，EXP/NORM读返回各4拍；这些浅层队列保留LUTRAM/寄存器实现，队列和tag不计入32 KiB行BRAM容量。输入/输出安全水位独立，禁止同周期同地址读写。

默认行间安排为`L0 → E0+L1 → N0 → W0+E1+L2 → N1 → …`。NORM独占output读写口；STORE旧行可与EXP新行重叠，但新e仅写入旧p已安全离开的地址。DDR停顿沿valid/ready传播，旧行输出地址及B响应上下文保留到事务结束。

## 1024×1024例子

每行1024个FP32=256个AXI beat=4 KiB，两块BRAM各使用前4 KiB。矩阵输入4 MiB、输出4 MiB，各262144个beat。

若一行由`[2,2+ln(0.75),2+ln(0.5),2+ln(0.25)]`重复256次构成，理想数学结果为max=2、exp=[1,0.75,0.5,0.25]：

~~~
E=[127,126,126,125]
M=[0x800000,0xc00000,0x800000,0x800000]
q=[2^48,3×2^46,2^47,2^46]
256组后T=A+B=640×2^48，S=640
p=[0.0015625,0.001171875,0.00078125,0.000390625]，重复256次
~~~

实际FP32输入与LUT存在舍入差异。重叠调度的理想主体周期估算为`(2M+2)×ceil(K/4)`；对1024×1024，主体估算为524800拍，250 MHz下约2.0992 ms。该估算未包含最大值流水排空、指数与归一化流水、行和转换、倒数、BRAM读返回和AXI停顿；完整周期及数值误差应由当前源码的回归和目标板测试测得。

## 验收与测量方法

功能测试应检查全部有效输出，并覆盖 K=1、非4倍数尾部、最大行长、mask、特殊浮点值、背压、AXI 错误和复位恢复。参考计算需使用稳定 Softmax，并分别记录最大绝对误差、最大行和误差及相对误差所用的 epsilon。

对 1024×1024 输入，每行 1024 个 FP32 对应 256 个 128-bit beat 和 4 KiB；矩阵输入、输出各 4 MiB，各需 262144 个 beat。两块 16 KiB 行缓存均只需占用每块前 4 KiB。一次完整运行还包括最大值阶段、指数/求和阶段、归一化阶段及 DMA 读写，不能将 II=1 直接换算成完整矩阵时延。

周期换算为时间时使用 t=C/f，其中 C 是明确界定的硬件周期数，f 是对应时钟。PYNQ 端到端时间还应分别计入数据准备、缓存同步、寄存器提交、硬件等待和结果读取；不要将测试平台周期当作板端 DDR 时间。
