# 方阵、宽矩阵、高矩阵统一结果

所有对齐形状和详细计时范围见 [完整实测数据 Markdown](DISPATCH_MATRIX_DETAIL.md)。

计算统一为 `A[M,K] @ B[K,N] -> C[M,N]`，按C的行列比例区分方阵、宽矩阵(N远大于M)、高矩阵(M远大于N)。
下表全部M/N/K本身32对齐；CPU四核四线程NEON，实际1049.9895 MHz，PL实际249.9975 MHz。
CPUFreq策略为1199999 kHz，不将其作为真实1.2 GHz实测。每项为9次中位数，单位ms。

每格按 **PS / PL** 排列。计时包括输入转换与搬运、B处理、缓存同步、提交、等待清状态、计算和C输出复制。
“B缓存命中”只指PL可复用已转置BT，PS当前仍每次打包B；“每次转置B”场景两条路径均每次处理B。
未启用DMA。两种场景分别独立测量，因此PS中位数存在小幅差异，不能把其中一个PS值混用作另一场景的精确基线。

## 交叉点口径

| 类型与固定条件 | B缓存命中时已测交叉点 | 每次转置B时已测交叉点 |
|---|---|---|
| 方阵M=N=K=D | D=224；D=192仍PS快 | D=256；D=224仍PS快 |
| 宽矩阵M=64,N=2048 | K=96；K=64仍PS快 | K=128；K=96仍PS快 |
| 高矩阵M=2048,N=64 | K=128已PL快；K=64仍PS快 | K=128已PL快；K=64仍PS快 |

高矩阵未测K=96，所以两种场景均只能确定交叉点在 `(64,128]`，不能称精确从K=128开始。
宽矩阵M=64按当前驱动的32行块分工只能使用两个核，不是所有表项都使用三核。
同一逻辑运算量也会因形状、活跃核数、权重转置和输出复制比例不同而产生不同交叉点。
不应把方阵边长阈值或单一 `2*M*N*K` 阈值作为所有形状的精确界限。

静态B首次调用不包含在“缓存命中”的9次稳态中位数中；例如 `(64,2048,736)`
修复后首次PL完整调用为6.303 ms（单次样本），而稳态缓存命中为3.048 ms。
K/N32对齐时静态B首次转置改为四线程NEON，已在板端通过临时模块验证。
正式runtime尚未替换，也尚未进行新版完整SmolVLA整图复测，因此本表不代表整图加速比。
