# A 使用 PS DMA，B 使用四线程 NEON 转置

2026-11-03 在 PYNQ GEMM_V2 实测。矩阵 A/B 为 INT8 2048×2048，C 为 INT32；三核行分工704/672/672，全部32行对齐。CPU选择1199999 kHz档，实际1049.9895 MHz；PL实际249.9975 MHz。

## 结果

每组预热1轮、测量8轮，三种方法轮换执行顺序，使用相同A/BT/C CMA地址。A输入内容每轮在两组数据间交替，每个结果都与四线程NEON参考逐元素比较。72轮正式结果和9次独立性能运行全部正确。

时间为中位数，单位ms。GOPS统一按2×2048³操作除以完整调用中位数计算。

| 核数 | CPU复制A，再转置B | DMA复制A，再转置B | DMA复制A与转置B并行 | 并行路径整体GOPS |
|---|---:|---:|---:|---:|
| 单核 | 55.923 | 55.418 | 55.262 | 310.88 |
| 双核 | 38.663 | 38.430 | 38.250 | 449.15 |
| 三核 | 33.884 | 32.749 | 32.701 | 525.36 |

三核同场CPU基线约507.01 GOPS，并行DMA约525.36 GOPS；完整耗时中位数减少1.184 ms，约3.49%。DMA并行比DMA串行仅少0.048 ms，不能认为并行具有稳定的额外优势。三核并行样本范围32.581–35.434 ms，CPU基线33.031–34.383 ms。

| 三核阶段 | CPU串行 | DMA串行 | DMA并行 |
|---|---:|---:|---:|
| A复制及必要同步 / DMA入队 | 2.555 | 2.253 | 0.206（入队） |
| 四线程NEON转置B | 6.601 | 5.707 | 7.692 |
| 完整输入准备 | 11.128 | 9.938 | 9.958 |
| GEMM提交至完成并清状态 | 13.397 | 13.376 | 13.389 |
| C同步并复制到独立普通内存 | 9.468 | 9.445 | 9.416 |

各阶段分别取中位数，因此不要求表中中位数相加等于总时间中位数。DMA并行时，A在工作线程执行阻塞ioctl；主线程调用原生四线程NEON转置。额外工作线程在DMA传输期间睡眠，不增加CPU核心数量。GEMM启动前会等待A DMA和BT/C同步全部完成。

## 为什么没有大幅加速

本次普通A内存经DMA API映射后为41段。已有试验驱动逐段提交并等待，会产生多次中断/唤醒。三核下DMA串行的实际ioctl约2.204 ms，其中缓存维护约1.019 ms、传输及分段等待约1.156 ms；并行时ioctl增至约2.503 ms，转置也变慢。DMA搬运和转置会争用CPU时间、缓存及内存资源，这次实验没有单独测量DDR带宽，不能据此把差异全部归因于DDR带宽。

三个方法的三核最大硬件周期分别3251435 / 3251221 / 3251509，约13.006 / 13.005 / 13.006 ms，基本一致。收益来自启动PL前的输入准备，GEMM硬件吞吐没有实质改变。

下一步可优化DMA驱动的散列表描述符批量提交和完成通知，并使用预注册输入缓冲池。当前结果没有实现或测量这些优化。

后续已经完成批量描述符及C输出DMA实测，详见 [README_DMA_BATCHED_AC.md](README_DMA_BATCHED_AC.md)。三核同时用批量DMA搬A和C、并避免对C CMA重复cache sync后，中位数为28.879 ms、约595 GOPS。

## 计时范围与限制

完整调用计入A复制、B转置、全部必需缓存同步、DMA ioctl及等待、GEMM提交/完成/清状态、C缓存同步和复制成独立输出。每轮输入生产、CMA分配、CPU参考及结果校验在计时外，三种方法边界一致。性能计数另跑，不混入正常延迟。

DMA页面固定和映射在初始化注册，本次约1.648 ms，不计入稳态调用。复用同一普通A数组和同一CMA目标时，只改内容即可；换A地址必须关闭旧映射并重新注册，不能把新地址当作已注册内存。若每次都需要重新注册，约1.65 ms开销可能抵消本次收益。此试验驱动固定4 MiB和XLNK后端，尚不是通用SmolVLA输入搬运接口。

DMA fd持有期间必须保留普通A和CMA分配。线程任务结束、DMA完成并关闭fd后才释放CMA。A的DMA路径由内核DMA API同步源和目标缓存，不能在DMA完成后额外对过期的CPU目标缓存进行写回。B/C仍使用PYNQ缓存同步。源和目标在传输中不允许并发CPU访问。

## 板端复现

脚本：`GEMM_V2/fast_gemm/benchmark_dma_input.py`。复用此前验证的模块：`smolvla_final/dma_trial_20261102/ps_dma_trial.ko`，通道`dma1chan0`，模块版本与当前Linux 5.4.0-xilinx-v2020.1匹配，不修改bitstream或PL时钟。

确认配套GEMM_V2已加载、无其他任务后，以root执行；只有本次加载的模块才由本次卸载：

```sh
set -eu
if [ ! -d /sys/module/ps_dma_trial ]; then
    insmod /home/xilinx/jupyter_notebooks/smolvla_final/dma_trial_20261102/ps_dma_trial.ko
    trap 'rmmod ps_dma_trial' EXIT
fi
cd /home/xilinx/jupyter_notebooks/smolvla_final/GEMM_V2/fast_gemm
python3 -u benchmark_dma_input.py --repeats 8
```

原始数据：`dma_input_results_20261103_053325.json`。主GEMM驱动保持原样，临时DMA模块在本次测试结束后已卸载。
